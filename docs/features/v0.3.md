## Notes

- IDs were renumbered once on 2026-10-10, before any work started, to match build order.
- F-0308 is blocked until the scale targets are set (budgets per cluster, total series, reconcile latency, query
  load). This is an open question in the HLD.
- 2026-10-13: F-0308 stays Blocked by decision: no cluster other than `kind-cb-dev` is allowed yet, and no
  scale targets are set.
- 2026-10-13 batch: F-0301 (hourly limit, `RateLimited`, `cardinalitybudget_drops_last_hour`), F-0302 (2 replicas,
  PDB, anti-affinity, leader election released on shutdown), F-0303 (NetworkPolicy on, threat model with RBAC
  review in `docs/security/threat-model.md`), F-0305 (alerts in `config/prometheus/alerts.yaml`, dashboard in
  `config/grafana/`, runbooks in `docs/runbooks/`), F-0306 (e2e matrix Kubernetes 1.35/1.36/1.37 with Prometheus
  Operator v0.94.1 plus v0.86.2 on 1.37; real Prometheus v3.13.4 LTS and v3.15.0; multi-arch build and Trivy),
  F-0307 (procedure in `hack/lab/verify-v0.3.md` Part 1). F-0304 is generated with the Kubebuilder helm plugin on Ubuntu.
- F-0302 "no double drops across a forced failover mid-step": in-cluster drill on kind with
  `kubectl delete pod <leader>` during an enforcement step; the enforcement mutex is per process, and only the
  leader reconciles, so the second replica starts from status and annotations (adoption covers a status write
  lost in the failover).
- The F-0306 e2e check names change (one per matrix row). Update the branch ruleset's required checks.
- 2026-10-19: v0.3 Done except F-0308. Lab: upgrade from v0.2 kept a v0.2 drop unchanged (F-0307); leader
  killed right after a drop, new leader in 3 s, next drop exactly one settle period later, no duplicate rule
  (F-0302); alerts `Paused`, `KillSwitchActive`, `MeasurementInvalid` and `OperatorDown` fired, all 7 rules
  loaded, the other three covered by tests (F-0305). F-0306 check names made unique in PR #16 (62a14ac).
- Helm replicas (2026-10-26): the helm plugin always generates `manager.replicas: 1`, even from a
  `dist/install.yaml` with 2 replicas, so it cannot be fixed by regenerating. `make helm-deploy` now sets
  `--set manager.replicas=$(HELM_REPLICAS)` (default 2), the chart test checks 2 ready replicas, and the
  README tells direct `helm install` users to set it. `kubebuilder edit --plugins=helm/v2-alpha --force`
  also overwrites `.github/workflows/test-chart.yml`: restore it after regenerating.
